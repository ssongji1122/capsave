## Design System

All font choices, colors, spacing, and aesthetic direction are defined there.

In QA mode, flag any code that doesn't match DESIGN.md.

## Development Process — TDD

All new features and bug fixes follow Red-Green-Refactor:

1. **RED**: Write failing test first
2. **GREEN**: Write minimal code to pass
3. **REFACTOR**: Clean up, keep tests green

Rules:
- No production code without a failing test
- Pure logic in testable modules (`shared/src/utils/` or `web/src/lib/`), not inline in routes/components
- API routes call extracted pure functions
- Test files: `__tests__/<module>.test.ts` colocated with source
- Test runner: vitest (shared, web), jest (mobile)

## 코딩 행동 원칙 (Karpathy 4원칙)

### 1. 가정 명시화 (Think Before Coding)
모호한 요청 수신 시 → 가정 목록화 + 선택지 제시 후 확인. 조용히 선택 금지.

### 2. 단순함 우선 (Simplicity First)
요청된 것만 구현. 단일 사용 코드에 추상화 금지 (재사용 2회부터 추출).

### 3. 외과적 변경 (Surgical Changes)
요청 범위만 수정. 무관한 정리/리팩터링 금지. 기존 스타일·import 순서 유지.

### 4. 목표 주도 실행 (Goal-Driven Execution)
완료 기준 합의 → 달성까지 루프. 측정 가능한 기준 (테스트 통과, 빌드 성공).
