# Scrave 앱인토스 캡처 시제품

사용자가 선택한 첫 범위는 캡처 선택·정리·보관함입니다. 브라우저에서 사진 한 장을 선택하고, 제목·분류·메모를 선택 사항으로 붙여 기기에 보관합니다. 같은 이미지를 다시 고르면 기존 기록을 열며, 검색과 분류로 다시 찾아 내용을 고칠 수 있습니다.

자동 분석은 연결하지 않았습니다. 기기에 저장하는 시제품이며, 계정별 동기화와 기존 Scrave 계정 연결은 후속 단계입니다. 기기나 브라우저의 데이터를 지우면 기록을 잃을 수 있으므로 보관용 서비스로 출시한 상태로 소개하지 않습니다.

## 구성과 검증

`src/archive.js`는 파일 검사·중복 식별·검색을 처리하고, `src/store.js`는 IndexedDB(브라우저가 기기에 보관하는 데이터베이스)에 이미지와 기록을 저장합니다. 저장 완료는 데이터베이스의 쓰기 작업이 끝난 시점에 표시합니다. 파일 이름과 메모는 화면에 글자로 넣으며 실행 코드로 해석하지 않습니다.

`src/main.js`는 브라우저의 사진 선택기를 사용합니다. `src/native.js`는 앱인토스 SDK(Software Development Kit, 토스 앱 기능을 사용하는 개발 도구 묶음)의 `Device.getAlbumItems`를 연결하는 별도 진입 파일입니다. 사용자가 도구 추가를 승인해 연결 도구 3.9.0과 Vite 6.4.5를 이 폴더에만 설치하고 잠금 파일을 만들었습니다. 기존 앱의 설치 파일은 바꾸지 않았습니다.

브라우저 빌드는 `dist`, 토스용 빌드는 `dist-toss`에 저장합니다. `build`와 `build:web`은 브라우저 화면을 만들고, `build:toss`는 토스용 화면과 `.ait` 번들을 만듭니다. 토스의 뒤로가기는 편집 화면에서 보관함으로 돌아가며 보관함에서는 미니앱을 닫습니다. 홈 버튼은 보관함으로 이동하고, 저장 중에는 두 버튼의 이동을 기다립니다.

브라우저는 선택 파일을 그대로 보관합니다. 토스용 경로는 앨범 도구가 돌려준 이미지 바이트를 보관하며, 요청한 최대 너비는 4096입니다. 이 경로가 사진첩의 전체 해상도 원본을 그대로 반환한다고 보장하지 않습니다.

```sh
node --test src/__tests__/*.test.js
```

로직 검사 열세 항목과 브라우저의 저장·재실행·검색·필터·수정·중복 선택·잘못된 파일 거부를 확인했습니다. 앨범 연결 다섯 항목과 탐색 연결 네 항목은 시험용 응답으로 확인한 검사이며, 실제 토스 앱의 동작 검증과 구분합니다. 화면 너비 320·390·768·1440과 200% 글자 확대에서 가로 넘침이 없었습니다. 새 도구로 만든 브라우저 빌드에서도 저장 후 새로고침해 이미지와 기록을 확인했고, 토스용 화면을 일반 브라우저에서 열었을 때 콘솔 오류와 경고는 없었습니다. 상세 근거는 [작업 기록](../../docs/coordination/2026-10-29_scrave-toss-capture-pilot.md)에 있습니다.

## 같은 결과 만들기

Node.js 24 이상에서 아래 명령을 저장소 루트에서 실행하며, `--prefix`와 `--workspaces=false`로 이 폴더의 설치와 실행을 지정합니다. 잠금 파일은 설치 당시 기준으로 고정했고, 새 버전을 추가할 때 `.npmrc`의 날짜를 다시 검토하도록 기록했습니다.

```sh
npm --prefix apps/toss --workspaces=false ci
npm --prefix apps/toss --workspaces=false test
npm --prefix apps/toss --workspaces=false run build:web
TOSS_APP_NAME=scrave-capture-pilot npm --prefix apps/toss --workspaces=false run build:toss
```

마지막 명령의 이름은 로컬 번들 검사에만 사용합니다. 실제 업로드 전에는 콘솔에 등록한 이름으로 바꿔 다시 빌드해야 합니다. 이름을 지정하지 않으면 설정이 오류를 내므로 등록 이름을 추측해 업로드하지 않습니다. `ait init`은 추가 개발 도구도 설치하는 동작이 있어 실행하지 않고, 설치한 연결 도구의 설정 형식을 확인해 직접 작성했습니다.

2026-10-30에 만든 `scrave-capture-pilot.ait`는 29,745바이트입니다. SDK의 번들 읽기 도구로 사진 읽기 권한만 들어 있는지, 압축 안의 화면 파일이 빌드 파일과 같은지 대조했습니다. SDK와 Vite의 패키지 검사에서 알려진 취약점은 0건이었습니다.

## 토스에서 시험하기 전

로컬 번들은 만들었으며 콘솔의 앱 식별 이름과 시험 권한은 실제 계정에서 확인해야 합니다. 현재 연결된 콘솔 도구가 없고, 사용자 브라우저 접근도 작업 환경에서 꺼져 있어 등록 상태를 확인하지 못했습니다. 앱 이름을 확인한 뒤 시험 업로드와 토스 실기기 시험을 진행합니다. 공개 출시는 이 단계에 포함하지 않습니다.

실제 토스 앱에서는 사진 선택·취소·권한 거부·지원하지 않는 앱 버전·뒤로가기·홈 버튼·저장 중 이동·재실행 후 보존을 확인해야 합니다. 브라우저 결과를 토스 실기기 검증으로 대체하지 않습니다. 출시용 사용자 식별과 저장 보장도 후속 검증 대상입니다.

기존 Google·카카오 로그인과 서버에서 만드는 웹 화면을 그대로 옮길 수 없다는 점은 [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md)과 [비게임 출시 가이드](https://developers-apps-in-toss.toss.im/checklist/app-nongame)에서 확인했습니다. 사진 선택 방식은 [앨범 선택 문서](https://developers-apps-in-toss.toss.im/documentation/sdk/domains-api/device/device.getalbumitems)를 따릅니다. 일부 개별 문서 주소가 열리지 않아 같은 공식 사이트의 [전체 문서](https://developers-apps-in-toss.toss.im/llms-full.txt)에서도 본문을 대조했습니다.
