## 작업 상태를 남기는 위치

이미 지정된 작업판·체크리스트·작업 브리프를 사용합니다. 복구할 때는 목표, 담당, 승인 범위, 다음 행동, 막힌 이유, 산출물 경로와 검증 결과를 확인합니다. 기록 위치가 지정되지 않은 새 작업은 해당 작업 문서에 이 항목을 기록하고, 병행 작업의 상태를 덮어쓰지 않습니다.

## 대화가 길어지거나 다시 시작할 때

Codex는 자동 압축 뒤 같은 채팅에서 계속합니다. 압축만을 이유로 새 채팅이나 인계 문서를 만들지 않습니다. Claude는 기존 전역 교대 절차를 따릅니다. 프로젝트별로 토큰 임계값을 복사하지 않습니다.

기억이 불명확해지면 현재 작업 기록과 관련 결정 원문을 다시 읽습니다. 파일 목록·참조 식별자·실행 결과를 요약에서 재구성하지 않습니다. 완료 상태는 실제 파일과 검증 결과로 확인하며, 승인·비용·공개 범위를 요약문만으로 넓히지 않습니다.

## 저장소를 수정하기 전

현재 브랜치와 변경 내역을 확인하고 다른 작업의 변경을 보존합니다. 원격 저장소가 있으면 최신 기록을 확인한 뒤 중복 구현 여부를 판단합니다. 다음 작업을 별도 브랜치나 위임으로 시작할 때는 열린 변경 요청과 최근 병합도 확인합니다. 인증·보호 파일·유료 호출의 기존 승인 경계는 유지합니다.
