# 링크 인입 계약

Scrave에서 링크 하나는 단순한 대화 참고가 아니라 새 자료를 받아들이라는 요청이다.
별도 설명이 없어도 원문을 읽고, 자료의 성격과 저장 위치를 판단해야 한다.

## 반드시 지키는 순서

1. 원본 URL과 게시물 작성자, 사용자가 지정한 이미지 순서를 보존한다.
2. 본문과 원본 이미지 묶음을 확보한다. 관련 없는 대체 이미지로 바꾸지 않는다.
3. 아래 분류 중 가장 가까운 하나를 고른다.
4. 분류에 맞는 추가 검증을 수행한다.
5. 검증 전에는 수집함에 두고, 검증 결과가 드러나는 상태로만 지식 창고나 수업자료 후보로 올린다.

## 자료 분류와 저장 위치

| 자료 성격 | 저장 위치 | 추가 확인 |
|---|---|---|
| 여행·맛집·카페·숙소 | 지도 자산 | 지역, 주소, 좌표, 현재 운영 정보, 지도 링크 |
| 마케팅 사례·캠페인·콘텐츠 전략 | 마케팅 참고자료 | 원 캠페인이나 당사자 출처, 적용 조건, 과장 여부 |
| 브랜드·아이덴티티·패키지 사례 | 브랜딩 참고자료 | 브랜드 공식 출처, 제작 시점, 디자인 맥락 |
| 도구 사용법·개념·학습 자료 | 학습 참고자료 | 공식 문서 또는 재현 결과, 버전과 재검토일 |
| 수업에 바로 쓸 만한 사례 | 수업자료 검토함 | 검증 판정, 확인일, 근거 링크, 적용 한계 |
| 어느 분류에도 확실히 맞지 않음 | 일반 참고자료 수집함 | 원문 보존 후 검토 필요 표시 |

## 승격 규칙

- 처음 받은 링크는 `captured` 상태다.
- 검증된 사실만 `verified`, 조건부 사실은 `qualified`로 올린다.
- 여행 자산은 좌표와 현재 운영 정보를 확인하기 전 지도에 확정 표시하지 않는다.
- 수업자료는 검증 판정과 확인일을 역추적할 수 있을 때만 사용한다.
- 원본 이미지 주소가 만료될 수 있으면 승격 전에 허용된 저장소에 원본을 보존한다.
- 애매한 자료는 버리지 않고 일반 참고자료 수집함에 둔다.

## 에이전트 실행

인스타그램 게시물은 다음 명령으로 원문, 이미지 묶음, 선택한 이미지 번호와 첫 분류를 확인한다.

```bash
node scripts/inspect-social-link.mjs "<Instagram URL>"
```

명령 결과의 `route`는 첫 분류다. 에이전트는 본문 전체와 원본 이미지를 보고 잘못된 분류를
바로잡을 수 있지만, 근거 없이 다른 주제나 대체 이미지를 만들면 안 된다.

장소 자산이면 실제 검색으로 위치와 운영 정보를 검증한다. 비장소 자산이면 해당 분류의
참고자료 저장소에 수집하고, 수업자료 승격 여부는 검증 게이트를 별도로 적용한다.
