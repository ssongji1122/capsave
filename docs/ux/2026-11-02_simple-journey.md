# 목표
캡처를 넣은 뒤 정리 방식을 선택하지 않아도 저장되고, 다시 찾았을 때 다음 행동 하나를 바로 실행할 수 있게 한다.

# 현재 코드에서 확인한 문제
- dashboard에 종류 필터와 활용 관점 필터가 중복된다.
- 업로드·가져오기·스티커북·사용 한도·보기 방식이 저장한 사진보다 먼저 나타난다.
- getVisibleArchiveCaptures는 실제 자료가 비어 있으면 샘플을 반환한다. 로딩·오류·빈 보관함을 구분하기 어렵다.
- 카드 상세에 같은 원문 링크가 행동 목록과 출처 목록에 반복된다.

# 화면 연결
보관함 → 캡처 추가 → 저장 중 → 저장된 카드 → 상세 → 지도/구매/원문
상세에서 뒤로 → 기존 보관함의 검색·분류·스크롤 위치 복원

# 1. 보관함
첫 화면은 my craves, 검색, 사진 카드. 추가 버튼은 항상 같은 위치에 둔다.
종류는 전체·물건·장소·정보·여행으로 한 번만 분류한다. 기본 정렬은 최근 저장순, 다른 정렬은 필터 안에 둔다.
카드에는 사진·짧은 제목·한 줄 요약. 사진을 누르면 상세로 이동한다.
하단 탐색은 보관함·추가·지도. 설정은 상단 계정 메뉴, 꾸미기는 보관함 메뉴에 둔다.
컬렉션과 가이드는 자료를 선택해 묶을 때 진입한다. 빈 컬렉션을 첫 화면의 필수 단계로 만들지 않는다.

# 2. 캡처 추가
사진 선택 → 원본 우선 보존 → 분석·출처 연결 → 같은 보관함에 카드 표시.
사용자는 분류·폴더·AI 제공자를 먼저 선택하지 않는다. 기존 설정을 사용한다.
처리 중에도 화면을 닫고 보관함을 볼 수 있어야 한다. 이 동작은 원본 보존 및 처리 상태 복구 구현 후 제공한다.
같은 게시물로 확인된 이미지들은 카드 하나에 묶고 1/N으로 표시한다.
실패하면 원본과 재시도 버튼을 남긴다. 재시도는 실패한 단계만 실행한다.

# 3. 상세
사진 묶음 → 제목·요약 → 주요 행동 → 더 보기 순서.
장소: 지도 보기. 물건: 구매처 보기. 정보: 원문 보기. 여행: 일정 확인.
검증된 게시물이 있으면 원문 보기로 연결하고, 업로드 이미지는 사진 확대에서 확인한다.
한 장소의 지도 서비스를 전부 나열하지 않는다. 기본 지도 하나와 다른 지도 선택을 제공한다.
더 보기: 출처 근거·전체 추출문·메모·태그·꾸미기·공유·삭제. 같은 주소는 한 번만 노출한다.
추정 장소는 후보로 표시하고 확정 위치처럼 저장하지 않는다.

# 상태별 화면
- 로그인 확인 중: 불러오는 중. 샘플 표시 금지.
- 비로그인: 기기에 저장한 자료 + 내 보관함 연결하기. 샘플은 별도 둘러보기에서만 제공.
- 로그인 후 빈 보관함: 첫 캡처 추가 안내.
- 불러오기 실패: 이전 자료 유지 + 다시 불러오기. 빈 상태나 샘플로 바꾸지 않음.
- 출처 미확인: 캡처는 저장됨, 출처만 확인 중/미확인 표시.

# 구현·검증 순서
1. 실제 데이터·샘플·로딩·오류 상태 분리.
2. 보관함 중복 탐색 제거와 추가 진입 통일.
3. 카드 상세 화면 연결 및 뒤로 가기 상태 복원.
4. 원본 저장 후 처리 상태 복원·단계별 재시도 확인.
5. 기존 저장 자료로 모바일 390px·데스크톱 검증, 지도·원문 이동 후 복귀, 배포 후 재확인.

이 문서는 현재 코드 분석에 따른 화면 설계이다. 새 화면 구현·배포 완료를 뜻하지 않는다.
