# 기존 모바일 Scrave 통합과 앱인토스 이식

2026-10-30 사용자가 기존 휴대폰용 Scrave에 디자인과 기능을 통합한 뒤 앱인토스에 넣는 방향을 승인했습니다. 담당은 현재 Codex 대화 세션이며 별도 수동 보관함 시제품은 시험 기록으로 보존합니다.

## 목표와 완료 기준

기존 모바일의 사진 선택 → 분석 → 저장 → 검색 → 원본·출처·실행 항목 → 장소·가이드 흐름을 최신 디자인으로 연결하고, 토스에서 다시 사용할 공통 코드를 분리합니다. 모바일 통합 완료와 토스 실행 완료는 따로 판정하며, 전체 목표는 실제 토스 호스트에서 선택·저장·재진입을 확인해야 완료합니다.

첫 단계의 확인 기준은 공통 코드·웹·모바일의 기존 검사 통과, 메모·처리 상태의 재열람, 지도 화면 디자인 일치, 저장한 가이드 재진입, 웹 원본 확대 오류 수정과 iOS 묶음 생성입니다. 실제 계정·휴대폰·토스 호스트 검증은 별도입니다.

## 기준과 작업 공간

최신 [디자인 기준](../../DESIGN.md)·[결정 원장](../../DECISIONS.md)의 2026-10-29 결정을 사용했습니다. 기준 소스는 `d5f31fd`이며 원격 main `6c5322c` 이후 로컬 디자인 변경을 포함합니다. 착수 직전 fetch·main 최근 기록·열린 변경 요청을 확인했고, 좌표·경로 후보 변경 요청 29·30과 겹치는 서버 코드는 수정하지 않았습니다.

작업 브랜치는 `codex/mobile-toss-integration`이며 기존 작업 폴더의 변경을 보존합니다. 공개 저장소의 푸시·공개 변경 요청·배포는 실행하지 않습니다. 계정 인증, 운영 데이터베이스, 유료 분석 호출과 보호 파일은 변경하지 않습니다.

## 반영한 내용

- 웹의 전화·예약번호·일정·주소·링크 추출과 저장 이유·메모·다시 보기·처리 상태 판정을 공통 코드로 옮겨 두 화면이 재사용합니다. 기존 웹 저장 형식을 유지합니다.
- 모바일 상세에 선택적인 저장 이유·메모, 다시 볼 시점, 여행·예약 고정, 명시적인 처리 완료와 되돌리기를 연결합니다. 열기·복사만으로 완료 표시를 바꾸지 않습니다.
- 모바일 보관함에서 여행·예약 / 처리할 일 / 다시 보기 목록을 선택하고 메모·저장 이유까지 검색합니다.
- 메모와 처리 상태는 기기의 계정별 파일에 보관합니다. 쓰기를 순서대로 처리하며 실패한 쓰기를 저장 성공으로 표시하지 않습니다. 캡처의 기존 서버 저장과 구분하며, 웹과 메모 동기화를 추가하지 않습니다. 기존 데이터베이스 구조를 변경하지 않습니다.
- 홈의 내 가이드에서 저장 목록과 동선을 다시 엽니다. 기존 장소 선택·초안 편집·저장 기능을 유지하고 기존 서버 조회 경로를 사용합니다.
- 모바일 지도 안내를 현행 밝은 테마로 맞추고 글자·화면 확대 제한을 제거했습니다. 지도 키와 인증은 변경하지 않았습니다.
- 웹 원본 확대를 카드 바깥의 화면 전체 창으로 옮겼습니다. 카드의 확대 효과에 잘리던 오류를 고쳤으며 Escape·키보드 초점·스크롤 복원을 확인합니다.

## 검증 근거

[검사 로그와 화면](../../output/mobile-integration/)에 결과를 보존합니다. 변경 전 실패하는 테스트를 확인한 뒤 구현했습니다. 최종 검사에서 웹 450개 통과·기존 조건부 3개 건너뜀, 공통 244개 통과, 모바일 90개 통과(전체 실행 89개와 후속 계정 전환 검사 1개)를 확인했습니다. 각 영역의 타입 검사와 공통 코드·웹 빌드를 통과했으며 iOS 묶음에서 새 메모 파일·화면·목록 판정 코드의 포함도 확인했습니다.

[실제 모바일 컴포넌트 검사 화면](../../output/mobile-integration/preview/index.html)은 별도의 예시 캡처를 사용합니다. 브라우저용 React Native 렌더러에서 메모 저장·명시적 완료·새로고침 후 재열람을 확인하며, 기기 파일 저장은 대체 저장소를 사용하는 컴포넌트 검사와 구분합니다. 이 화면을 실제 휴대폰·토스 실행 증거로 사용하지 않습니다. 390px 화면과 200% 확대에서 문서 가로 폭이 390px로 유지됐고 주요 버튼의 최소 높이는 44px였습니다. 메모에서 Tab 키로 다음 선택 버튼에 진입했으며 동작 줄이기 설정에서 검사했습니다. React Native Web의 기존 pointerEvents 경고 1건이 있으나 최종 화면 로드의 콘솔 오류는 0건이었습니다.

로컬 웹 실제 화면에서도 확대 창이 카드 바깥의 390×844 전체 화면을 차지하고, Escape로 닫은 뒤 원래 확대 버튼에 초점이 돌아오는 것을 확인했습니다. [확대 검사 로그](../../output/mobile-integration/web-modal-check.log)를 보존합니다. 로그인 전용 가이드·설정 화면의 사전 요청에서 로컬 500 응답 2건이 있어 해당 계정 화면은 검증 완료로 판정하지 않습니다.

## 앱인토스 설치와 이식

[공식 React Native 시작 문서](https://developers-apps-in-toss.toss.im/ai-vibe-coding/tutorials/react-native.md)는 Granite 1.x(토스에서 React Native 화면을 실행하는 개발 환경), `@apps-in-toss/framework`, TDS(Toss Design System, 토스 공통 화면 구성 요소)를 안내합니다. 지원하는 네이티브 모듈 범위와 샌드박스 검증이 필요하므로 기존 Expo 설치 파일을 그대로 업로드하지 않습니다.

2026-10-30 사용자가 표의 도구와 공식 실행 기반 설치·이식을 승인했습니다. npm 등록 정보와 공식 생성기의 실제 템플릿을 확인한 뒤 `integrations/toss-native`에 독립적으로 설치했습니다. 기존 Expo와 루트 설치 파일은 유지했습니다. npm 작업 공간의 `apps/*`에 넣으면 공식 도구가 상위 설치를 선택해 빌드에 실패하므로 승인한 별도 폴더를 작업 공간 밖으로 배치했습니다. 표의 직접 의존성과 하위 설치에는 7일 유예 기준을 적용했습니다.

| 도구 | 고정 후보 | 확인 내용 |
|---|---|---|
| Granite와 관련 생성·라우터·Hermes 도구 | 1.0.45 | 2026-09-16 배포를 확인했습니다. 공식 생성기의 필수 구성과 맞춥니다. |
| 앱인토스 React Native 연결 도구 | 2.10.13 | 2026-10-07 배포를 확인했습니다. 앞서 설치한 웹용 3.9.0과 다른 패키지이며 3.9.0을 임의로 지정하지 않습니다. |
| 토스 화면 구성 요소 | 2.0.5 | 2026-08-08 배포를 확인했습니다. 연결 도구의 요구 조건 2.0 이상을 만족합니다. |
| 화면 실행 기반 | React 19.2.3 / React Native 0.84.0 / brick-module 0.5.1 | 공식 Granite 1.0.45 생성기의 템플릿 값입니다. 기존 Expo의 React 19.2.0 / React Native 0.83.6과 구분합니다. |

화면·분류·메모 판정은 재사용하고 사진 선택·기기 저장·화면 이동·글꼴·지도는 토스가 지원하는 연결로 바꿉니다. Google·카카오 로그인과 토스 로그인을 같은 계정으로 자동 연결하지 않습니다. 인증 변경은 별도 설계와 승인 대상입니다.

설치 비용은 0원이며 유료 분석·서버 배포·서비스 등록은 진행하지 않았습니다. [토스 폴더 사용 안내](../../integrations/toss-native/README.md)에 고정 버전·명령·저장 방식과 제약을 기록했습니다.

기존 모바일 `CaptureWorkflowView`를 그대로 재사용하고 실행 연결만 주입합니다. 목록 검색·저장 이유·여행 묶음·처리할 일·다시 보기 판정도 기존 모바일과 공통 코드에서 가져오며 분류 도형은 웹과 같은 경로를 사용합니다. 토스의 실제 앨범·기기 저장·복사·외부 링크 함수를 연결했습니다. 사진·직접 입력한 내용은 토스 기기 보관함에 저장하고 기존 서버 계정과 연결하지 않습니다. 계정 연결 전 자동 분석·기존 캡처·내 가이드까지 토스에 이식했다고 판정하지 않습니다.

공식 `ait build`가 React Native 0.84.0·0.72.6 각각의 iOS·Android 묶음과 `scrave-local.ait`를 만들었습니다. 등록 전 로컬 검사 이름이며 실제 콘솔 이름·아이콘으로 다시 빌드해야 합니다. [빌드 로그](../../output/mobile-integration/toss-native-build.log)와 [타입 검사](../../output/mobile-integration/toss-native-typecheck.log)를 보존합니다.

토스 전용 기능 검사 13개는 선택·취소·저장·메모·명시적 완료·새 화면에서 재열람·동시 수정·초기 로딩 경합·손상 데이터 보존·실패 후 재시도·복사 권한 실패·안전한 링크 연결을 확인합니다. 대체 저장소·토스 연결 도구를 사용하는 검사이며 실제 호스트 호출 성공으로 세지 않습니다. [토스 검사 로그](../../output/mobile-integration/toss-native-tests.log)를 보존합니다. 기존 모바일 91개·공통 244개·웹 450개 검사를 통과했고 웹의 기존 조건부 검사 3개는 건너뛰었으며 모바일 타입 검사·공통 빌드·웹 빌드를 다시 확인했습니다.

[브라우저 검사 화면](../../output/mobile-integration/preview/toss.html)은 실제 토스용 화면 코드를 React Native Web으로 렌더링하며 앨범·저장·토스 버튼·벡터 렌더러를 대체합니다. 시험용 이미지와 예약번호로 저장·메모·완료·새로고침 후 재열람을 확인했습니다. 390px 화면에서 가로 폭은 390px이고 주요 조작 높이는 44px 이상이었습니다. SUIT는 이 검사 페이지에서만 웹 글꼴로 불러오므로 토스의 글꼴 증거로 사용하지 않습니다. 200% 확대에서도 가로 폭 390px와 저장한 메모·완료 상태를 유지했습니다. 동작 줄이기를 켰고 최종 흐름의 콘솔 오류는 0개, 기존 React Native Web pointerEvents 경고는 1개였습니다. [측정 기록](../../output/mobile-integration/toss-browser-measurement.log)을 남겼습니다.

공식 iOS 샌드박스 앱을 iPhone 17 Pro 시뮬레이터에 설치해 실행했습니다. [실제 로그인 화면](../../output/mobile-integration/toss-sandbox-login.png)까지 확인했으며 개발자 로그인과 앱 등록·선택이 필요해 Scrave 실행으로 이어가지 못했습니다. 시뮬레이터 설치 성공을 토스에서 사진·저장을 검증한 것으로 판정하지 않습니다.

SUIT의 토스 글꼴 등록 경로, 실제 저장 한도와 계정 전환 범위는 미확인입니다. 설치 직후 보안 검사에서 전체 의존성 46개에 경고를 보고했고 치명적 경고 1개는 개발 서버의 하위 패키지입니다. 버전 강제 교체나 보안 설정 변경은 하지 않았으며 [관련 보안 공지](https://github.com/advisories/GHSA-72c6-fx6q-fr5w)와 실제 영향·수정 호환성을 공개 배포 전에 검토해야 합니다.
