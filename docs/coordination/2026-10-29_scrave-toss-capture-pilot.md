# Scrave 앱인토스 캡처 시제품 작업 기록

## 목표와 승인 범위

사용자가 2026-10-29에 앱인토스에 Scrave를 넣어 보고 싶다고 요청하고, 첫 범위로 ‘캡처 선택·정리·보관함부터 시험합니다’를 골랐습니다. 담당은 이 문서를 작성한 Codex 대화 세션입니다. 수락 기준은 실제 사진 선택·기기 저장·재열람·분류·메모·검색을 연결하고, 토스에서 시험하기 위해 남은 조건을 구분하는 것입니다.

이번 시제품은 직접 분류와 메모를 붙이는 흐름부터 시험합니다. 토스 로그인·운영 데이터 변경·유료 분석 호출·공개 저장소 게시·출시는 실행하지 않았습니다. 사용자가 2026-10-30에 앱인토스 도구와 Vite를 별도 폴더에 추가하도록 승인했습니다. `apps/toss`에만 설치했으며 루트의 패키지와 잠금 파일은 기존 내용을 유지했습니다.

## 기존 작업과 공식 요구의 대조

원격을 갱신해 `origin/main`의 `6c5322ce0e7e69b6f6a411ddab2a3500877308ad`와 최근 다섯 커밋을 확인했습니다. 열린 변경 요청은 [좌표 저장 30](https://github.com/ssongji1122/capsave/pull/30)과 [경로 후보 29](https://github.com/ssongji1122/capsave/pull/29)였으며, 이 작업은 두 범위를 수정하지 않습니다. 기존 작업 폴더의 변경을 보존하기 위해 별도 작업 폴더와 `feat/toss-capture-pilot` 브랜치를 만들었습니다.

## 2026-10-30 도구 설치와 번들 확인

사용자가 승인한 `@apps-in-toss/web-framework` 3.9.0과 Vite 6.4.5를 정확한 버전으로 설치하고, 전체 의존성은 이 폴더의 `package-lock.json`에 고정했습니다. 새 버전 유예 기간을 적용해 2026-10-23 이전에 나온 패키지만 선택했습니다. 번들 형식 도구가 요구하는 Node.js 24는 컴퓨터에 이미 있는 24.14.0으로 실행했습니다. 패키지 검사에서 알려진 취약점은 0건이었습니다.

처음 설치 뒤 잠금 파일을 갱신하는 명령이 루트 작업공간을 선택해 루트 잠금 파일에 변경을 만들었습니다. 이 작업이 만든 변경만 원래 내용으로 되돌린 뒤, 저장소 루트에서 `--prefix apps/toss --workspaces=false`를 지정해 설치·검사를 다시 실행했습니다. 루트 패키지와 잠금 파일의 최종 차이는 없습니다.

`ait init` 소스를 확인했더니 승인한 두 도구 외의 개발 도구도 자동 추가하므로 실행하지 않았습니다. 설치한 SDK의 설정 형식으로 `apps-in-toss.config.ts`를 작성했으며, 사진 읽기 권한·밝은 탐색 막대·뒤로가기·홈 버튼을 지정했습니다. `TOSS_APP_NAME=` 값은 매번 명시해야 하고 로컬 검사 이름을 기본 등록 이름으로 저장하지 않습니다.

검증 명령은 다음과 같으며 저장소 루트에서 Node.js 24로 실행했습니다.

```sh
npm --prefix apps/toss --workspaces=false ci
npm --prefix apps/toss --workspaces=false test
npm --prefix apps/toss --workspaces=false run build
TOSS_APP_NAME=scrave-capture-pilot npm --prefix apps/toss --workspaces=false run build:toss
```

로컬 검사 이름으로 만든 `.ait` 파일은 29,745바이트이고, 구성 파일은 사진 읽기 권한 하나만 포함합니다. SDK가 제공하는 번들 읽기 도구로 파일 다섯 개를 확인했으며, 안에 들어 있는 화면 파일 세 개의 바이트가 `dist-toss`의 실제 파일과 일치했습니다. SHA-256(파일이 같은지 확인하는 해시값)은 `e8c1f48fe4f93394dd04cdfc3abd8a1b698aa812ba9d044d38cda439fe1b9c40`입니다. 상세 실측은 작업 폴더의 `output/toss-bundle-verification.json`에 남겼습니다.

새 브라우저 빌드에서 시험용 캡처를 저장하고 새로고침한 결과는 `cards=1`, `imageLoaded=true`, `width=390`, `scroll=390`이었습니다. 화면은 `output/playwright/1030-browser-build.png`에 보관했습니다. 토스용 빌드도 별도 브라우저에서 화면을 읽고 사진 추가 오류 복구를 확인했으며, 콘솔 오류 0건·경고 0건이었습니다. 토스 호스트가 없는 브라우저이므로 실제 앨범·탐색 동작 검증으로 세지 않습니다.

## 다음 단계와 현재 상태

현재 상태는 도구 설치·토스 번들 빌드·브라우저 검증 완료, 콘솔 등록 이름 확인 대기, 토스 실기기 미검증입니다. 연결된 토스 콘솔 도구가 없고 사용자 브라우저 접근도 작업 환경에서 꺼져 있어 등록 상태를 직접 조회하지 못했습니다. 사용자에게 등록한 `appName` 또는 미등록 여부를 요청했습니다. 현재 로컬 검사 이름을 등록된 앱으로 간주하지 않습니다.

2026-10-30에 사용자가 ‘미등록’이라고 답했습니다. 첫 등록 절차와 제안값은 [콘솔 등록 안내](../../apps/toss/CONSOLE-SETUP.md)에 준비했습니다. `Scrave`·비게임·`scrave`를 제안하되, 영문 식별 이름의 사용 가능 여부와 최종 확정은 콘솔에서 확인해야 합니다. 다음 필요한 계정 작업은 로그인 후 최초 앱 등록이며, 등록한 실제 이름을 받으면 번들을 다시 만듭니다.

콘솔 이름 확인 → 해당 이름으로 재빌드 → 비공개 시험 업로드 → 토스 앱에서 사진 선택·취소·권한 거부·저장·재진입·뒤로가기·홈 버튼 확인 순서로 진행합니다. 시험 업로드와 공개 출시는 구분하며, 토스 실기기 검증 전에는 앱인토스 이식 완료로 표시하지 않습니다.

토스 안에서 설치 없이 저장 경험을 시험할 수 있다는 장점이 있습니다. 반면 기존 로그인과 서버 화면의 차이 때문에 전체 앱을 그대로 옮기는 부담이 있습니다. 따라서 사용자가 고른 캡처 흐름을 먼저 시험하고, 같은 저장 기록을 기존 앱과 잇는 범위는 실제 이용 결과를 보고 정하도록 추천합니다. [Medium: 구현 순서 제안]

공개 푸시·변경 요청·머지·배포는 실행하지 않았습니다.


## 2026-10-30 — 등록 전 전체 앱 점검을 우선합니다

사용자가 콘솔 등록 전에 기존 앱의 전체 기능·디자인부터 확인하도록 요청했습니다. 위의 등록 대기 상태보다 이 순서를 우선하며 최초 등록은 보류합니다. [전체 기능·디자인 점검](2026-10-30_scrave-app-audit.md)과 [화면 비교판](../../_dogfood/2026-10-30_scrave_app-audit_v1.html)에 운영 화면·최신 슬레이트 소스·시제품의 차이를 남겼습니다. 웹·모바일·공통 검사 771개와 타입 검사를 통과했고, 실제 로그인·유료 분석·휴대폰·토스 호스트 검증은 남았습니다. 2026-11-02에 이 목록을 재검토하거나 사용자가 범위를 정하면 먼저 갱신합니다.

현재 순서는 기존 앱 점검 → 이식 범위 정리 → 최신 화면 연결 → 토스 비공개 시험 → 출시 판단입니다. 시제품 작업을 전체 기능 이식 완료로 판정하지 않습니다. 공개 저장소의 푸시·PR·운영 배포와 계정 작업은 실행하지 않았습니다.

원본 확대의 실제 화면 재검사에서 창이 카드 안에 갇히는 오류를 재현했습니다. 사전 점검의 우선 수정 항목으로 기록했으며 서비스 코드와 운영 배포는 변경하지 않았습니다.


### 기존 모바일 통합을 우선 검토합니다

사용자가 원래 만들던 휴대폰용 Scrave에 디자인과 기능을 통합하고 앱인토스로 옮기는 방향을 제안했습니다. 별도 수동 보관함의 기능 확대를 멈추고 [전체 앱 점검 문서의 후속 방향](2026-10-30_scrave-app-audit.md)을 우선합니다. 기존 시제품·검사·번들은 시험 근거로 보존합니다. 실제 모바일 통합 구현과 토스용 실행 환경 전환은 아직 하지 않았습니다.
