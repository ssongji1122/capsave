# Scrave 완성 목표와 실행 계약

작성일: 2026-11-04
목표 상태: 진행 중
현재 작업 브랜치: `codex/scrave-mobile-resilience` (기반 브랜치: `codex/scrave-product-finish`)

## 최종 요청문

> Scrave를 실제로 매일 사용할 수 있는 완성형 개인 아카이브 제품으로 만들어 줘. 먼저 현재 저장소·열린 PR·최근 main·결정 원장·통합 작업판·디자인 시스템을 감사해서, 이미 된 것·부분 완료·미구현·막힌 것을 근거와 함께 한 화면의 진행 사이트로 만들어. 그다음 그 판을 기준으로 웹과 모바일 앱을 TDD(Red–Green–Refactor, 실패 테스트부터 구현하는 개발 방식)로 완성해. 핵심 흐름은 이미지·스크린샷·링크 저장, AI 분석 결과 확인·수정, 장소/텍스트/카테고리 분류, 검색·필터·재발견, 원본 보존, 웹·모바일 동기화야. 모호한 제품 방향·비용·보안·데이터 마이그레이션만 내 결재를 받고, 그 외 구현·테스트·리팩터링·커밋·PR·CI·기존 배포 경로·배포 후 확인은 자율 진행해. 가짜 데이터나 껍데기 화면, TODO, 부분 구현은 금지하고, 실제 데이터와 실패·빈 상태·오프라인·권한 거부·재시도까지 검증해. 각 단계마다 수락 기준과 실측 증거를 진행 사이트에 갱신하고, 부족한 부분을 계속 찾아 고쳐서 핵심 사용자 시나리오가 실제 기기 또는 동등한 실행 환경에서 처음부터 끝까지 통과할 때만 완료로 선언해. 기존 사용자 변경과 시크릿은 보존하고, 유료 API·외부 공개·파괴적 변경은 사전 결재를 받아.

## 완료 기준

### 1. 상태를 한 판에서 판단할 수 있습니다

- 최신 `origin/main`, 열린 PR, 결정 원장, 작업판, 코드와 실제 실행 결과를 대조합니다.
- 완료·부분 완료·차단·다음 행동을 기능별로 나누고 각 항목에 증거를 연결합니다.
- `_dogfood/2026-11-04_scrave_product-status_v1.html`에서 모바일과 데스크톱으로 읽을 수 있습니다.

### 2. 웹 핵심 여정이 통과합니다

- 이미지 한 장·여러 장 업로드, 분석 결과 확인, 저장, 삭제, 한도 초과가 동작합니다.
- 공개 Instagram 게시물·릴스 링크에서 원문·작성자·전체 미디어를 순서대로 검사하고 `수집됨 · 확인 전`으로 저장합니다.
- 장소·텍스트·검색·정렬·연관 카드·원본·출처·지도·가이드·스티커 흐름을 회귀 검증합니다.
- 비로그인과 로그인 흐름, 실패·빈 상태·지도 인증 실패를 검증합니다.

### 3. 모바일 핵심 여정이 통과합니다

- 사진 선택, 권한 거부, 분석·저장, 보관함·상세·장소·텍스트·가이드가 동작합니다.
- 공개 Instagram 게시물·릴스 링크에서 원문·작성자·전체 미디어를 확인하고, 저장 실패 지점부터 다시 시도할 수 있습니다.
- 단위 테스트와 타입 검사뿐 아니라 Expo 번들 또는 시뮬레이터 빌드가 성공합니다.
- 실제 계정·실기기에서만 확인할 수 있는 항목은 통과로 가장하지 않고 별도로 표시합니다.

### 4. 다시 실행할 수 있는 품질 게이트가 있습니다

- 공통·웹·모바일 테스트, 타입 검사, 프로덕션 빌드, 브라우저 사용자 여정을 한 명령 흐름으로 재현할 수 있습니다.
- 보안 감사의 직접 의존성 위험과 앱 스토어 출시 차단 항목을 기록하고, 승인 없이 해결할 수 있는 항목은 수정합니다.
- 변경 뒤 같은 검증을 다시 실행해 회귀가 없음을 확인합니다.

### 5. 완료 선언은 실제 증거로만 합니다

- 유료 AI 호출, 실제 OAuth, Apple/Google 개발자 계정, 운영 데이터 변경은 기존 승인 경계를 유지합니다.
- 코드·문서·테스트·빌드·실행 화면이 일치할 때만 완료로 표시합니다.
- 남은 계정 액션이 있으면 정확히 한 개의 다음 행동과 영향을 적습니다.

## 검증 기준선

2026-11-04 최신 `origin/main`(`000e7a0`)에서 확인했습니다.

- 열린 변경 요청은 [드래프트 PR #30](https://github.com/ssongji1122/capsave/pull/30) 한 건입니다. 장소 좌표 캐시, 지도, 가이드, 공통 캡처 타입과 겹치므로 통합 전 현재 브랜치의 검색·지도·가이드 회귀 검사가 필요합니다.
- shared: 275개 통과
- web: 554개 통과, 3개 의도적 건너뜀
- mobile: 151개 통과
- `npm run verify:core`로 세 작업공간 테스트 980개와 타입 검사 통과
- Next.js 15.5.29·sharp 0.35.5에서 웹 프로덕션 38개 경로 빌드 통과
- `npm run test:e2e`가 격리된 웹 서버와 테스트 전용 인증 환경을 자동으로 띄우며 Playwright 53개 사용자 여정을 통과
- `/import`에서 공개 Instagram 링크를 붙여 넣어 원문·작성자·전체 미디어를 확인하고, 저장 뒤 보관함에서 같은 게시물 묶음으로 다시 여는 Chromium 여정을 320px 화면에서 통과
- Expo iOS 번들 1,750개 모듈·154개 자산 내보내기 통과
- Expo Android 번들 1,763개 모듈·162개 자산 내보내기 통과. 설치 가능한 Android 네이티브 산출물은 패키지 이름과 `android/` 프로젝트가 없어 아직 만들지 않았습니다.
- 최신 iOS·Android 내보내기의 `metadata.json`에서 `openaiApiKey`·`aiProvider`·Supabase·Google 설정 필드가 모두 없음을 값 노출 없이 확인했습니다. 현재 내보내기는 설정값을 포함하지 않습니다. `app.config.ts`와 클라이언트 분석 코드에는 OpenAI 키 주입 경로가 남아 있어, 제거 승인 전까지 구조적 위험으로 분류합니다.
- 웹 단일·묶음 분석과 모바일 분석 화면에 저장 전 검토·수정 단계를 추가했습니다. 분류·제목·요약·추출 글·장소 이름·주소·날짜를 고칠 수 있고, 장소 식별 정보가 바뀌면 오래된 좌표·장소 링크 캐시를 제거합니다. 제목·장소 검증, 저장 실패 뒤 초안 유지, 게스트 잔여 횟수 초과 가입 안내를 실패 테스트부터 고정했으며 Chromium 핵심 여정 53개가 다시 통과했습니다.
- 모바일 분석 초안을 수정한 뒤 상단 뒤로가기나 Android 시스템 뒤로가기를 누르면 폐기 확인을 거치며, iOS 화면 밀기 제스처가 확인 절차를 우회하지 못하게 했습니다. 저장 중에는 뒤로가기를 막습니다. 관련 실패 테스트 3개와 양 플랫폼 Expo 내보내기가 통과했습니다.
- Xcode iOS Simulator arm64 네이티브 빌드 통과: `/tmp/scrave-derived/Build/Products/Debug-iphonesimulator/Scrave.app`
- 환경변수를 빌드 프로세스에만 주입한 Xcode Release arm64 시뮬레이터 앱이 깨끗한 파생 캐시에서 빌드됐고, 산출물의 `UIUserInterfaceStyle=Light`를 확인했습니다. 같은 앱이 iPhone 17 Pro에서 첫 실행과 콜드 재실행 후 로그인 화면까지 도달했습니다.
- Supabase 설정이 없는 깨끗한 개발 실행에서 `createClient('', '')`가 앱 시작 전에 예외를 내던 문제를 실패 테스트 4개로 재현했습니다. 초기화를 지연하고, 값 대신 필요한 `EXPO_PUBLIC_SUPABASE_URL=`·`EXPO_PUBLIC_SUPABASE_ANON_KEY=` 이름만 보여 주는 설정 화면으로 바꿨습니다. iPhone 17 Pro 시뮬레이터에서 RedBox 없이 화면이 렌더링되는 것을 확인했으며, 개발 클라이언트 열기 팝업은 macOS 잠금 때문에 닫지 못한 상태로 캡처했습니다. 근거 이미지는 `_dogfood/assets/2026-11-04_scrave-product-status/mobile-missing-config.png`입니다.
- Supabase 설정만 있고 Google iOS 클라이언트 ID가 없는 실행에서는 인증 훅이 화면 렌더링 전에 예외를 내는 문제를 실측했습니다. 플랫폼별 필수 Google 설정을 실패 테스트 4개로 고정하고, iOS에서는 `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID=`, Android·웹에서는 `EXPO_PUBLIC_GOOGLE_CLIENT_ID=`가 없을 때 같은 안전 안내 화면을 보여 줍니다. iPhone 17 Pro 시뮬레이터 재실행에서 기존 `iosClientId must be defined` 오류가 사라진 것을 확인했습니다.
- 분석·후기·출처·링크·가이드가 모바일 서버 주소를 서로 다르게 해석해, 설정이 비면 일부 기능만 즉시 실패하던 문제를 실패 테스트 3개로 고정했습니다. `SCRAVE_SERVER_URL` 빌드값, `EXPO_PUBLIC_API_URL=`, 기존 운영 주소 순서의 공통 해석기로 통일했습니다. 운영 기본 주소 `https://scrave.vercel.app`은 루트 HTTP 200, 비로그인 `/api/guides` HTTP 401로 정상 응답함을 확인했습니다.
- 구성값을 모두 넣은 무서명 iOS 시뮬레이터에서는 Keychain 권한 부재가 Supabase 자동 갱신의 처리되지 않은 오류로 반복됐습니다. 보안 저장소가 실패하면 디스크에 다른 값을 쓰지 않고 현재 프로세스 메모리에서만 세션을 유지하도록 실패 테스트 2개를 추가했습니다. 완전 재실행 뒤 로그인 화면이 렌더링되고 처리되지 않은 오류가 다시 나오지 않았으며, 세션이 재실행 뒤 유지되지 않는다는 경고 1건만 남았습니다. 서명 빌드에서는 기존 SecureStore를 그대로 사용합니다.
- 모바일 홈에서 설정 화면을 열어 기본 내비게이션 앱을 고르고 기존 `user_preferences`에 저장할 수 있습니다. 저장 성공 뒤에만 선택값을 바꾸며, 실패·잘못된 서버 값·계정 전환 중 늦은 응답을 안전하게 처리합니다. 캡처 카드·상세·빠른 지도 메뉴·지도 핀의 네 메뉴가 모두 선택한 앱을 첫 항목으로 표시합니다. 관련 모바일 테스트 14개를 추가했고, 시뮬레이터 화면 조작은 Mac 잠금 해제 뒤 확인할 항목으로 남겼습니다.
- 웹 설정도 서버 저장 오류를 성공으로 오인하지 않고 기존 선택을 유지하며, 불러오기·저장 실패와 재시도를 표시합니다. 공통 제공자 검증과 웹 회귀 테스트 11개를 추가했고, Chromium에서 선택·저장·새로고침 복원까지 통과했습니다.
- 키체인 권한이 없는 실행 환경에서 인증 초기화가 무한 로딩으로 남던 문제를 실패 테스트 3개로 재현하고, 로그아웃 상태로 안전하게 시작하도록 수정했습니다.
- 사진 권한 거부·영구 차단·취소·선택 실패를 분리하고, 영구 차단 시 운영체제 설정으로 이동할 수 있게 했습니다. 관련 모바일 테스트 5개를 추가했습니다.
- 로그인 계정과 일치하는 SQLite 사본만 앱 시작 즉시 보여 주고, 서버 동기화 실패 시 사본 유지·오프라인 안내·재시도를 제공합니다. 로그아웃 때 데이터와 계정 표식을 모두 지우며, 계정 전환 중 늦게 도착한 요청은 현재 화면을 덮지 않습니다. 관련 모바일 테스트 12개를 추가했습니다.
- 메모·저장 이유·다시 보기·완료 상태와 스티커 배치는 웹 `localStorage` 및 모바일 계정별 로컬 파일에만 저장됩니다. 현재 `captures`와 `user_preferences` 스키마에는 이 값을 보관할 열이 없어, 기기 간 동기화는 데이터베이스 마이그레이션 결재와 충돌 규칙 확정 전까지 완료로 셀 수 없습니다.
- 기존 캡처 행을 확장하지 않는 `capture_user_metadata`·`capture_decorations` 보조 테이블과 revision 기반 충돌 처리, 로컬 자료 첫 동기화 순서를 [결재안](../plans/2026-11-04_capture-state-sync-approval.md)으로 정리했습니다. 마이그레이션 파일 작성과 운영 적용은 수행하지 않았습니다.
- `app.config.ts`의 밝은 화면 설정과 체크인된 iOS `Info.plist`의 어두운 화면 설정이 달랐던 문제를 실패 테스트로 재현하고 `Light`로 맞췄습니다.
- 프로덕션 의존성 감사는 47건(치명적 2)에서 41건(치명적 0)으로 줄였습니다. 남은 직접 위험은 Expo SDK·React Native 큰 버전 마이그레이션 범위입니다.
- Expo Doctor는 20개 중 18개를 통과했습니다. 권장 패치 정렬은 프로덕션 보안 경고를 41건에서 65건으로 늘려 되돌렸고, 체크인된 iOS 프로젝트와 앱 설정의 수동 동기화 경고는 위 회귀 테스트로 감시합니다.
- 현재 iOS·Android 내보내기에는 `openaiApiKey`와 `aiProvider` 필드가 없고, 빌드 프로세스의 `OPENAI_API_KEY=`도 비어 있음을 값 노출 없이 확인했습니다. 다만 값이 주입되면 서버용 키를 앱 설정에 포함할 수 있는 비상 경로와 클라이언트 직접 호출 코드가 남아 있습니다. 현재 기본값은 서버 분석이며, 이 경로 제거는 보안 변경 결재 뒤 진행합니다.
- 제거 대상 파일, 실패 테스트, 회귀 검증, 서버 장애 시 트레이드오프를 [모바일 OpenAI 직접 호출 제거 결재안](../plans/2026-11-04_mobile-openai-fallback-removal-approval.md)에 확정했습니다. 코드와 설정은 아직 변경하지 않았습니다.
